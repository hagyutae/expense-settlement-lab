# 경비 청구 데이터 스키마

경비 정산 시스템이 읽어 들이는 청구 파일의 형식과, 그것을 담는 도메인 모델의 속성을 정합니다. `samples/` 폴더의 파일이 모두 이 형식을 따릅니다.

**컬럼명이 곧 속성명입니다.** 파일의 헤더와 `Expense` 의 속성이 같은 이름이므로 둘 사이에 대응표가 필요 없습니다.

## 파일 형식

| 항목 | 값 |
|---|---|
| 확장자 | `.csv` (Markdown 표 지원은 실습 과제입니다) |
| 인코딩 | UTF-8 with BOM (`utf-8-sig`) |
| 구분자 | 쉼표 |
| 줄바꿈 | CRLF, LF 모두 허용 |
| 첫 줄 | 헤더 행. `Expense` 의 속성명과 정확히 일치해야 합니다 |

날짜는 파일에서 모두 `YYYY-MM-DD` 형식입니다. 조건부 항목은 해당 조건이 아니면 빈 문자열로 둡니다.

Excel에서 저장할 때는 "CSV UTF-8(쉼표로 분리)"을 선택하세요. 일반 "CSV"로 저장하면 한글이 깨집니다.

```csv
claim_id,employee_id,employee_name,department,used_date,claim_date,expense_type,amount,payment_method,merchant,merchant_category,evidence,attendees,receipt_no,card_no,bank_account,resident_no,note
EXP-2026-0417,E20391,김민준,영업1팀,2026-03-14,2026-03-20,식비,42000,법인카드,이온식당 강남점,음식점,Y,3,R-20260314-0092,5327-8812-4405-1043,,,
EXP-2026-0418,E20391,김민준,영업1팀,2026-03-15,2026-03-20,교통비,18500,개인카드,카카오T,교통,Y,,,4092-7731-0084-2215,,,법인카드 한도 초과로 개인카드 사용
```

## 도메인 모델

`core/domain/models.py` 에 클래스 이름만 있으므로 아래대로 채웁니다. **이름은 계약이므로 바꾸지 않습니다.**

### Expense

청구 한 건입니다. 18개 컬럼의 원본 문자열을 `raw: dict[str, str]` 에 그대로 담고, 같은 이름의 속성으로 꺼내 씁니다. **타입** 열은 속성이 갖는 파이썬 타입입니다.

| 속성 | 뜻 | 타입 | 필수 | 예시 |
|---|---|---|---|---|
| `claim_id` | 청구ID | `str` | 필수 | `EXP-2026-0417` |
| `employee_id` | 사번 | `str` | 필수 | `E20391` |
| `employee_name` | 성명 | `str` | 필수 | `김민준` |
| `department` | 부서 | `str` | 필수 | `영업1팀` |
| `used_date` | 사용일자. 실제로 지출한 날 | `date \| None` | 필수 | `2026-03-14` |
| `claim_date` | 청구일자. 정산 시스템에 올린 날 | `date \| None` | 필수 | `2026-03-20` |
| `expense_type` | 계정과목 | `str` | 필수 | `식비` |
| `amount` | 금액. 원 단위, 부가세 포함, 쉼표 없이 | `int \| None` | 필수 | `42000` |
| `payment_method` | 결제수단 | `str` | 필수 | `법인카드` |
| `merchant` | 가맹점 | `str` | 필수 | `이온식당 강남점` |
| `merchant_category` | 가맹점업종 | `str` | 필수 | `음식점` |
| `evidence` | 적격증빙 보유 여부. `Y` 또는 `N` | `str` | 필수 | `Y` |
| `attendees` | 참석인원. 식비·접대비일 때 입력 | `int \| None` | 조건부 | `4` |
| `receipt_no` | 영수증번호. 3만원 초과 건에 입력 | `str` | 조건부 | `R-20260314-0092` |
| `card_no` | 카드번호. 카드 결제일 때 입력 | `str` | 조건부 | `5327-8812-4405-1043` |
| `bank_account` | 계좌번호. 현금 청구의 환급 계좌 | `str` | 조건부 | `신한 110-482-773915` |
| `resident_no` | 주민등록번호. 원천징수 대상 건에만 입력 | `str` | 조건부 | `890412-1029384` |
| `note` | 비고. 사전승인 번호, 개인카드 사용 사유 | `str` | 선택 | `사전승인 A-2026-0031` |

네 속성은 정해진 값만 옵니다.

| 속성 | 허용 값 |
|---|---|
| `department` | `영업1팀` `개발2팀` `마케팅팀` `경영지원팀` `연구소` |
| `expense_type` | `식비` `접대비` `교통비` `숙박비` `도서구입비` `소모품비` `통신비` `교육훈련비` |
| `payment_method` | `법인카드` `개인카드` `현금` |
| `merchant_category` | `음식점` `주점` `교통` `숙박` `서점` `문구` `통신` `기타` |

`used_date` `claim_date` `amount` `attendees` 넷은 파싱한 값입니다. **파싱에 실패해도 예외를 던지지 않고 비웁니다.** 값이 잘못되었는지 판단하는 것은 규칙의 몫입니다. R001은 `raw` 의 값이 빈 문자열인지 보고 R002는 `amount` 가 비었거나 0 이하인지 보므로, 모델이 예외를 던지면 이 둘이 검사할 대상이 사라집니다.

### Violation

규칙 하나가 잡아낸 위반입니다.

| 속성 | 타입 | 설명 |
|---|---|---|
| `code` | `str` | `R001` 형식의 규칙 코드 |
| `name` | `str` | 규칙 이름. `필수 항목 누락` |
| `message` | `str` | 반려 사유. `경비규정.md` 의 인용문 |

`code` 와 `name` 은 위반을 만든 규칙이 갖고 있는 값을 그대로 넣습니다.

### Judgement

청구 한 건의 판정입니다.

| 속성 | 타입 | 설명 |
|---|---|---|
| `expense` | `Expense` | 판정 대상 |
| `violations` | `list[Violation]` | 위반 목록. 규칙 코드 순 |
| `is_passed` | `bool` | `violations` 가 비면 참 |

### SettlementResult

정산 한 번의 결과 전체입니다.

| 속성 | 타입 | 설명 |
|---|---|---|
| `judgements` | `list[Judgement]` | 판정 목록. 입력 순서를 유지합니다 |

판정 목록을 담을 뿐이지만 따로 두는 이유는 처리 단계가 내는 것과 출력 단계가 받는 것을 같은 타입으로 맞추기 위해서입니다. 나중에 필드가 늘어도 `settle` 과 `format` 의 시그니처가 바뀌지 않습니다.

## 개인정보 안내

`samples/` 폴더의 카드번호, 계좌번호, 주민등록번호는 실습을 위해 생성한 가짜 값입니다. 실제 개인정보가 아닙니다.

이 값들은 규칙 판정에 사용하지 않습니다. 지급 처리를 위해 원본 데이터에 함께 들어 있는 항목이며, 챕터 6 보안 실습에서 마스킹 대상으로 다룹니다.
